# 地理试卷打标验证规则

## 一、格式验证规则

### 1.1 必需字段验证

**检查项**：
- exam_info字段是否存在
- sections字段是否存在
- sections是否是数组
- sections数组长度是否 >= 1

**判定规则**：
- 如果缺少必需字段 → 格式验证失败
- 如果字段类型错误 → 格式验证失败

---

### 1.2 字段类型验证

**检查项**：
- exam_info是否是对象
- exam_name是否是字符串
- subject是否是字符串（且为"地理"）
- section_id是否是数字
- question_number是否是数字

**判定规则**：
- 如果类型不匹配 → 格式验证失败

---

### 1.3 结构完整性验证

**检查项**：
- 每个section是否包含section_id、section_type、question_groups
- 每个question_group是否包含group_id、questions
- 每个question是否包含question_number、question_type

**判定规则**：
- 如果结构不完整 → 格式验证失败

---

## 二、逻辑验证规则

### 2.1 题号连续性验证

**检查项**：
- 提取所有题号
- 检查题号是否重复
- 检查题号是否跳跃过大（允许跳号，但不允许无序）

**判定规则**：
- 如果题号重复 → 逻辑验证失败
- 如果题号无序（如1, 5, 3） → 逻辑验证失败
- 如果题号跳号合理（如1, 2, 17） → 逻辑验证通过

**示例**：
- 正确：[1, 2, 3, 4, 5] 或 [1, 2, 17, 18]
- 错误：[1, 2, 2, 3] 或 [1, 5, 3]

---

### 2.2 选项完整性验证

**检查项**：
- 选择题是否包含ABCD四个选项
- 选项内容是否为空
- 选项是否是对象（不是数组）

**判定规则**：
- 如果选择题缺少options → 逻辑验证失败
- 如果缺少ABCD任意一个选项 → 逻辑验证失败
- 如果选项内容为空 → 逻辑验证失败

**示例**：
- 正确：{"A": "...", "B": "...", "C": "...", "D": "..."}
- 错误：{"A": "...", "B": "..."}（缺少CD）

---

### 2.3 题组归属验证

**检查项**：
- 检查group_id是否合理（如"1-2"或"17"）
- 检查题组范围是否合理（group_id为"1-2"时，题目应为1和2）
- 检查题目是否属于某个题组

**判定规则**：
- 如果group_id格式不合理 → 逻辑验证失败
- 如果题组范围不匹配 → 逻辑验证失败

**示例**：
- 正确：group_id="1-2"，questions包含题号1和2
- 错误：group_id="1-2"，questions包含题号1和3

---

### 2.4 图片引用验证

**检查项**：
- 图片引用是否是字符串数组
- 图片文件名格式是否正确（如img_001.png）
- 图片引用是否与images文件夹对应

**判定规则**：
- 如果图片引用格式错误 → 逻辑验证失败
- 如果图片引用不对应 → 逻辑验证失败（可选）

---

## 三、置信度判定规则

### 3.1 置信度等级

| 等级 | 条件 | 说明 |
|------|------|------|
| high | 双轨都通过格式验证+逻辑验证，且结果一致 | 最可靠 |
| medium | 单轨通过验证，或双轨通过但不一致 | 可靠但需确认 |
| low | 仅逻辑验证通过，或格式验证部分通过 | 不太可靠 |
| failed | 格式验证和逻辑验证都失败 | 不可靠 |

---

### 3.2 判定流程

```
检查格式验证：
  ├─ 双轨都通过 → 继续检查逻辑验证
  ├─ 单轨通过 → confidence = medium
  └─ 双轨都失败 → confidence = failed

检查逻辑验证：
  ├─ 双轨都通过 → 继续对比结果
  ├─ 单轨通过 → confidence = medium
  └─ 双轨都失败 → confidence = failed

对比结果一致性：
  ├─ 完全一致 → confidence = high
  ├─ 部分一致 → confidence = medium
  └─ 完全不一致 → confidence = low
```

---

## 四、融合策略规则

### 4.1 融合优先级

**优先级排序**：
1. AI结果（AI理解更准确）
2. 脚本结果（脚本确定性高）
3. 空结果（双轨都失败）

**判定规则**：
- 如果AI结果格式验证通过 → 优先采用AI结果
- 如果AI结果格式验证失败，脚本通过 → 采用脚本结果
- 如果双轨都失败 → 输出空JSON

---

### 4.2 差异标记规则

**标记方式**：
- 在最终JSON中添加merge_details字段
- 记录不一致的字段和两个版本的值

**示例**：
```json
{
  "exam_info": {
    "exam_name": "AI版本：2025年海南..."
  },
  "merge_details": [
    {
      "field": "exam_info.exam_name",
      "ai_value": "2025年海南...",
      "script_value": "海南省2025...",
      "decision": "采用AI结果"
    }
  ]
}
```
