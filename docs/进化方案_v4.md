# shijuan-paiban 进化方案 v4

> 从「散文规则 + LLM 手写 LaTeX + 人眼看 PDF」进化到「数据化规则 + 确定性渲染 + 可执行评分」。

---

## 0. TL;DR

当前技能的瓶颈**不是覆盖率，是一致性**：同一份试卷跑两次结果不同，改一条规则不知道会不会破坏另一条，`evals.json` 里 22 条评估用例没有一行可执行代码。

进化分四层，建议按 P0 → P1 → P2 → P3 顺序推进：

| 阶段 | 目标 | 产出 | 工作量 |
|------|------|------|--------|
| **P0 止血** | 消除规则矛盾，建立单一事实源 | `rules/layout.yaml` + 清理腐化 | S |
| **P1 可测** | 让"变好还是变坏"可回答 | `scripts/eval_run.py` + 金标样本 + 基线分 | M |
| **P2 确定性** | 排版决策从 LLM 手里拿走 | Question IR + `scripts/render_tex.py` | L |
| **P3 自进化** | 失败自动沉淀成规则 | 失败归因 + A/B 门禁 + 规则库 | M |

**关键判断：P1 必须先于 P2。** 没有评分基线就重构渲染层，等于蒙眼换发动机。

## 1. 诊断：六个结构性问题

### 1.1 规则自相矛盾（同一件事有两种说法）

LLM 每次执行会随机选一条，这是输出不稳定的直接来源。

| # | 矛盾点 | 位置 A | 位置 B |
|---|--------|--------|--------|
| 1 | 单张图片最大宽度 | `SKILL.md:294` 「不得超过 `0.35\textwidth`」 | `SKILL.md:362` 「❌ 超过 `0.30\textwidth`（单张，默认）」 |
| 2 | 图片对齐方式 | `SKILL.md:332` 「始终用 `\centering`，**禁止** `\raggedleft`」 | `README.md:207` 「单张无子问用 `[H]` + `\raggedleft`」 |
| 3 | 教师版模式数量 | `SKILL.md:529` 三模式（compact/normal/exam），后缀 `-教师版-紧凑` / `-教师版` / `-教师版-考试` | `SKILL.md:673` 编译 `文件名-教师版-答题空间.tex`（旧两模式命名）；`evals.json` id 13/14 仍按 onepage/space 两模式断言 |

第 3 条尤其严重：步骤 5 生成的文件名和步骤 6 编译的文件名对不上，**流程本身是断的**。

### 1.2 评估不可执行

`evals/evals.json` 有 22 条用例，字段如 `"page_count": 4`、`"has_tasks_env": true`、`"no_overfull_errors": true`——但**没有任何脚本读取这个文件**。

结果：改一条规则后，唯一验证手段是"再跑一份试卷、肉眼看 PDF"。这在小改动上还能撑，规则一多就崩。

> 环境其实是齐的：`xelatex` / `pandoc` / `pdfinfo` / `pdftoppm` 本机全部可用。评估跑不起来纯粹是缺 harness，不是缺条件。

### 1.3 转换逻辑双轨，互不复用

- **交互路径**：LLM 读 SKILL.md → 逐题手写 LaTeX（不可复现、不可测）
- **批量路径**：`scripts/md2tex.py`（42KB，含完整清洗/结构修复逻辑）→ 确定性输出

同一份内容走两条路结果不同，且 `md2tex.py` 里积累的大量修复经验（`clean()` 里的 PUA 字符清理、`\neqslant` 纠正、`wrap_text_cmds` 等）**完全没有反馈到交互路径**。等于批量流水线踩过的坑，交互路径要再踩一遍。

### 1.4 新脚本悬空，没接进工作流

v3 改进新增了四个脚本，但 SKILL.md 里引用次数：

| 脚本 | SKILL.md 引用次数 | 状态 |
|------|------------------|------|
| `auto_adjust.py` | 0 | 写了但工作流不用 |
| `table_convert.py` | 0 | 同上 |
| `visual_verify.py` | 0 | 同上（步骤 6 仍在用裸 `pdftoppm`） |
| `gen_paper.py` | 0 | 同上 |

`validate_tex.py` 只被引用 1 次，且没有说明"验证失败后怎么办"的分支。

### 1.5 可移植性缺陷

| 问题 | 位置 | 后果 |
|------|------|------|
| `find ~/.claude/skills` 硬编码 Claude Code 路径 | `SKILL.md` ×3 | 换到 WorkBuddy / 其他宿主即失效；skill 引用自己的脚本不该靠全局搜索 |
| `D:\Music\试题加题库` 硬编码 | `SKILL.md:779` | 只在本机成立 |
| 依赖外部 `docx` skill 的 `unpack.py` | `SKILL.md:209` | 实际只需 10 行 `zipfile` 就能替代，却引入一个跨 skill 依赖 |
| `run_build.bat` 用 `%%~dp0` | 根目录 | `.bat` 里应为 `%~dp0`，说明这个文件**从未跑通过** |

### 1.6 仓库腐化

| 文件 | 问题 |
|------|------|
| `scripts/md2tex_v1.py`（34KB） | 死代码，与 `md2tex.py` 并存 |
| `scripts/fix_md_corruptions.py` / `fix_md_corruptions2.py` | 一次性脚本，无入口 |
| `scripts/fix_errors.py` / `fix_error_answers.py` | 同上 |
| `scripts/installers/*.exe` | Git 安装器放在 skill 仓库里 |
| `run_build.bat` / `simple_test.bat` / `texput.log` | 根目录 scratch 文件（`simple_test.bat` 内容就是 `echo Hello`） |

另外 `SKILL.md:711` 的清理命令 `rm -f .aux .log .out` 是错的——缺通配符，实际什么都删不掉。

### 1.7 潜伏 bug（顺带记录）

`SKILL.md:577` 的 `gen_teacher.py` 用硬编码 `start_num = 15` 和 `content.find(r"\begin{examenum}[start=15, itemsep=2.5cm]")` 定位解答题块。若实际 `itemsep` 不是 `2.5cm`（而 SKILL.md 自己在多处推荐改成 1.5~2.0cm），`find()` 返回 `-1`，脚本会**静默产出错误文件**而不是报错。

## 2. 核心判断

### 为什么现在"改不动"

这个技能的复杂度集中在一个地方：**排版决策**（8 种图片场景怎么选、`tasks` 几列、`itemsep` 多大、何时 `minipage` 何时 `wrapfigure`）。

这些决策目前全部以**自然语言散文**形式存在，靠 LLM 每次现场重新推理。于是：

```
规则写在散文里
  → 无法被代码检查（validate_tex 只能查括号配对、$ 配对这类语法）
  → 无法被测试（没有断言对象）
  → 加规则只会让散文更长更冲突（SKILL.md 从 564 行涨回 864 行）
  → 冲突无法被发现（因为没有测试会失败）
```

**这是负反馈缺失下的规则膨胀。** 继续往 SKILL.md 加规则，边际收益递减，边际风险递增。

### 进化方向

把知识从散文搬进**代码和数据**，让每条规则都有 ID、有断言、有证据。

```
L0 一致性：规则变成数据（rules/layout.yaml），文档从数据生成 → 不可能矛盾
L1 可测性：eval runner 跑真试卷，产出分数 → 改动有反馈
L2 确定性：排版决策交给 renderer，LLM 只产结构 → 结果可复现
L3 自进化：失败归因 → 规则候选 → A/B 验证 → 入库 → 分数上升
```

四层是递进的：没有 L0 就没有可断言的规则，没有 L1 就无法验证 L2 的重构是否等价，没有 L2 就没有结构化的失败信号供 L3 消费。

## 3. 目标架构

```
                    ┌──────────────────────────────┐
   DOCX / PDF  ───► │  提取层 extract              │  pandoc / MinerU / zipfile
                    │  → 原始 Markdown + 图片       │
                    └──────────────┬───────────────┘
                                   ▼
                    ┌──────────────────────────────┐
                    │  理解层（LLM 唯一职责）        │
                    │  题目切分 / 公式 / 表格 / 图   │
                    │  → paper.json（Question IR）  │
                    └──────────────┬───────────────┘
                                   ▼
                    ┌──────────────────────────────┐
                    │  渲染层 render_tex（确定性）   │  ← rules/layout.yaml
                    │  编号 / 环境嵌套 / tasks 列数  │
                    │  图片场景 / 答题空间 / itemsep │
                    └──────────────┬───────────────┘
                                   ▼
                    ┌──────────────────────────────┐
                    │  验证层 compile + validate     │
                    │  → scorecard.json（带 rule_id）│
                    └──────────────┬───────────────┘
                                   ▼
                    ┌──────────────────────────────┐
                    │  进化层 evolve                │
                    │  失败归因 → 规则候选 → A/B     │
                    └──────────────────────────────┘
```

关键变化：**LLM 的产出从"一页 LaTeX"变成"一份 JSON"**。LaTeX 由代码生成，因此可复现、可单测、可 diff。

## 4. 分阶段方案

### P0 止血：单一事实源（工作量 S，约 1 天）

**目标**：消灭矛盾，建立"规则只有一处定义"的机制。

**做什么**

1. 新建 `rules/layout.yaml`，把散落的规范参数收拢成带 ID 的数据：

```yaml
# 每条规则有唯一 ID，validate_tex / render_tex / 文档生成器共用
- id: IMG-W-001
  scope: image
  name: 单张题目配图最大宽度
  value: "0.30\\textwidth"
  applies_when: "单图且无子问"
  evidence: "10 份试卷实测，0.35 时图注溢出页边"

- id: IMG-ALIGN-001
  scope: image
  name: 图片对齐
  value: "\\centering"
  forbidden: ["\\raggedleft"]
  rationale: "raggedleft 导致图注不对齐"

- id: TASKS-COL-001
  scope: options
  name: tasks 列数判定
  type: decision_table
  rules:
    - when: "has_image and avg_len < 80"
      value: 4
    - when: "has_image and avg_len >= 80"
      value: 2
    - when: "has_formula or avg_len > 25"
      value: 2
    - when: "default"
      value: 4

- id: PAGE-ITEMSEP-001
  scope: spacing
  name: 解答题 itemsep
  type: formula
  expr: "clamp(available_space / saq_count, 1.2, 2.5)"
```

2. `scripts/gen_rules_doc.py`：从 YAML 生成 SKILL.md / README 里的规则表格，用标记块包裹：

```markdown
<!-- RULES:IMG-W-001:BEGIN -->
| 单张配图最大宽度 | `0.30\textwidth` |
<!-- RULES:IMG-W-001:END -->
```

改规则只改 YAML，跑一次生成器，文档自动同步。**物理上不可能再矛盾。**

3. 修复 §1.5 的可移植性：`~/.claude/skills` → 相对 SKILL.md 的 `$SKILL_DIR`；`docx` skill 依赖 → 内置 `scripts/extract_docx.py`（zipfile 十行）；`D:\Music` → 配置项。

4. 清理 §1.6：删 `md2tex_v1.py`、4 个一次性 fix 脚本、`installers/`、根目录 3 个 scratch 文件。修 `SKILL.md:711` 的清理命令。

**验收**

- [ ] `grep -c "0.35\\textwidth" SKILL.md` 结果为 0（或仅出现在生成区块内）
- [ ] `python scripts/gen_rules_doc.py --check` 返回 0（文档与 YAML 一致）
- [ ] `grep -rc "~/.claude/skills" .` 结果为 0
- [ ] 三个 `tests/test_*.py` 全绿

**风险**：低。纯整理，不改流程语义。

### P1 可测：eval runner（工作量 M，约 2-3 天）

**目标**：让"改规则是变好还是变坏"变成可回答的问题。

**做什么**

1. `scripts/eval_run.py`——真正执行 `evals/evals.json` 的 harness：

```bash
python scripts/eval_run.py --fixtures evals/fixtures --out reports/
# → reports/scorecard.json + reports/report.md
```

执行链：`输入文件 → 提取 → 转换/渲染 → xelatex ×2 → validate_tex → 打分`

2. **检查项分三级**（全部确定性，不引入 LLM 判分）：

| 级别 | 检查项 | 权重 | 说明 |
|------|--------|------|------|
| HARD | `compiles` / `no_undefined_cs` / `all_images_exist` | 一票否决 | 任一失败该用例记 0 |
| STRUCT | `env_per_section` / `examenum_start` / `tasks_cols` / `no_wrapfigure_in_list` / `answer_space_count` / `graphicspath_match` | 各 1 分 | 从 tex 源码断言 |
| LAYOUT | `page_count` / `overfull_count` / `dollar_balance` | 各 0.5 分 | 从 log/pdfinfo 断言 |

3. **金标样本**：在 `evals/fixtures/` 放 6-8 份真实试卷（覆盖：标准卷 / 答案卷 / 扫描件 / 多图几何 / 表格 / 长选项多选），每份附 `expected.json`。

> 图片体积大时用 `fixtures/manifest.json` 引用外部路径，CI 只跑 manifest 里标记 `local: true` 的用例。

4. **记录基线分**：`reports/baseline.json`。之后任何改动，跑一次 eval，分数低于基线就拒绝合并。

**验收**

- [ ] `python scripts/eval_run.py` 一条命令跑完全部 fixture
- [ ] 输出含总分、按 category 的分数、失败项对应的 `rule_id`
- [ ] 基线分写入 `reports/baseline.json`
- [ ] 故意改坏一条规则（如把 `itemsep` 固定为 10cm），eval 分数必须下降

**风险**：中。fixture 制作需要人工确认"什么是正确输出"。建议先用 3 份最典型的试卷起步，跑通再扩。

### P2 确定性内核：Question IR + renderer（工作量 L，约 5-7 天）

**目标**：把排版决策从 LLM 手里拿走，让输出可复现、可单测。

**核心设计：LLM 只产 JSON，代码产 LaTeX**

```jsonc
{
  "meta": {
    "title": "2024年普通高等学校招生全国统一考试（新高考Ⅰ卷）",
    "subject": "数学",
    "template": "gaokao",
    "total_pages": 4,
    "is_answer": false,
    "images_dir": "media",
    "answer_space": "normal"          // compact | normal | exam
  },
  "sections": [
    {
      "heading": "一、单项选择题：本题共8小题，每小题5分，共40分。",
      "type": "choice_single",         // choice_single | choice_multi | fill_blank | long_answer
      "questions": [
        {
          "no": 1,
          "stem": "已知集合 $A=\\{x \\mid x^2-3x+2=0\\}$，则 $A\\cap B=$",
          "images": [],
          "options": [
            { "label": "A", "text": "$\\{1\\}$" },
            { "label": "B", "text": "$\\{2\\}$" }
          ],
          "layout_hint": "auto"        // auto | 2col | 4col | image_side
        },
        {
          "no": 9,
          "stem": "如图，在四棱锥 $Q-ABCD$ 中……",
          "images": [{ "file": "image12.png", "caption": "第9题图" }],
          "subquestions": ["证明：$BQ \\perp AD$；", "求平面 $QAD$ 与 $QBC$ 夹角的余弦值．"],
          "points": 13,
          "raw_tex": null              // 逃生舱：极特殊情况直接给 LaTeX
        }
      ]
    }
  ]
}
```

**分工边界**

| 环节 | 谁做 | 为什么 |
|------|------|--------|
| 题目切分、公式、表格、图片归属 | LLM | 需要语义理解 |
| `tasks` 列数 | renderer | 规则确定（`TASKS-COL-001`），LLM 判断不稳定 |
| 图片场景选择（8 选 1） | renderer | 规则确定（`IMG-*`） |
| `examenum` start 值 | renderer | 纯算术，LLM 常算错 |
| 答题空间插入位置 | renderer | 位置确定（每 item 末、末题除外） |
| `itemsep` 分配 | renderer | 公式（`PAGE-ITEMSEP-001`） |
| 表格 / TikZ / 罕见结构 | LLM（`raw_tex`） | 无法枚举 |

**为什么这不是从零重写**：`md2tex.py` 已经是一个事实上的 renderer（MD → tex，含结构修复）。P2 的本质是**把它的排版逻辑抽出来、配上显式 IR、并让交互路径复用同一份**。不是新建，是统一。

**同时获得的能力**

- renderer 可以单测：给定 `paper.json` fixture，断言输出 tex 逐字节一致 → `tests/` 从"手搓 check() 脚本"升级为真正的回归测试
- 同一份 IR 渲染 student / teacher / onepage 三个版本，教师版生成不再是字符串 hack（消灭 §1.7 的静默 bug）
- 支持"改模板不改内容"：换 `template` 字段重新渲染即可

**验收**

- [ ] `render_tex.py` 对 6 份 fixture IR 渲染结果通过全部 STRUCT 检查
- [ ] 同一 IR 渲染两次输出完全一致（可复现性）
- [ ] `tests/test_render.py` 覆盖 8 种图片场景 + 3 种答题空间模式
- [ ] P1 的 eval 总分 ≥ 基线（不允许退化）

**风险**：高。这是唯一可能失败的阶段。缓解：
- `raw_tex` 逃生舱保证任何题目都能表达
- 分两步走：先只接管"编号 + 环境嵌套 + tasks 列数"（最容易错、最容易测），图片场景暂时仍由 LLM 决定；跑稳后再接管图片
- 全程以 P1 分数为护栏

### P3 自进化：失败归因 → 门禁（工作量 M，约 3 天，之后持续）

**目标**：让每次失败都沉淀成规则，且沉淀过程有验证。

**做什么**

1. **结构化失败日志**（替代现在的自由文本日志）：

```jsonc
// log-runtime/<task>/failures.json
[
  { "rule_id": "IMG-W-001", "question_no": 9,
    "symptom": "图注超出右边距 3.2pt",
    "evidence": "overfull \\hbox (3.2pt too wide) in paragraph at lines 214--216" }
]
```

2. `scripts/evolve.py`：按 `rule_id` 聚合失败，按频次排序，输出规则候选：

```bash
python scripts/evolve.py --logs log-runtime/ --min-support 3
# → rules/candidates.yaml
```

3. **A/B 门禁**：候选规则自动跑 P1 eval，分数 ≥ 基线才进入待审队列；人工确认后合入 `rules/layout.yaml` 并生成文档。

4. 规则库带 `evidence` 字段——每条规则能追溯到它解决的真实案例。**没有证据的规则不允许进库**，这是防止规则膨胀的关键约束。

**验收**

- [ ] 一次真实排版任务后，`failures.json` 自动生成且含 `rule_id`
- [ ] `evolve.py` 能从历史日志里跑出至少 1 条候选
- [ ] 候选规则的 A/B 报告可读（改前分 / 改后分 / 影响用例）

**风险**：低。纯增量，不影响主流程。

---

## 5. 不建议做的事

| 想法 | 为什么不建议 |
|------|-------------|
| 继续往 SKILL.md 加规则 | 当前 864 行已含 3 处硬矛盾；不加断言地加规则是净负收益 |
| 用 LLM-as-judge 做主要评分 | 不确定性叠加不确定性。确定性检查（编译/页数/环境）先跑满，成本低且稳定 |
| 把模板改成脚本全生成 | LaTeX 排版细节（`wrapfigure` 浮动、`minipage` 对齐、`tasks` 断行）无法穷举，必须保留模板文件 |
| 重写 `md2tex.py` | 它的清洗逻辑是踩坑踩出来的（PUA 字符、`\neqslant`、伪 span），重写等于重新踩一遍。P2 是**抽取复用**，不是重写 |
| 上 CI | 单人项目，本地 `eval_run.py` + 基线分足够。等 P2 稳定、需要多机复现时再说 |
