## 🤖 Assistant

下面给你一套“从零重构”的可落地方案。目标不是让 AI 一次做完，而是把整条链路拆成“可控、可验证、可回滚”的多步技能系统。

**总体原则**
- 主 Skill 只负责编排，不负责内容理解。
- 每个子 Skill 只做一件事，且有固定输入、固定输出。
- 所有关键结果都落盘成文件，后一步只读取前一步产物，不依赖上下文记忆。
- 最重要的是先定 `JSON Schema`，再写 Prompt；不要反过来。

**目录建议**
- `skills/master_exam_layout.md`
- `skills/clean_exam.md`
- `skills/tag_structure.md`
- `skills/tag_placeholders.md`
- `skills/tag_images.md`
- `skills/map_images.md`
- `skills/typeset_exam.md`
- `schemas/exam_paper.schema.json`
- `templates/exam_reference.json`
- `docs/pipeline.md`
- `docs/error_cases.md`

**流程设计**
- 第 1 步：清洗
  - 输入：原始试卷文件
  - 输出：`cleaned/content.md`、`cleaned/images/`
- 第 2 步：结构打标
  - 输入：`cleaned/content.md`、参考 JSON 模板
  - 输出：`stage/structure.json`
- 第 3 步：图片占位
  - 输入：`stage/structure.json`
  - 输出：`stage/with_placeholders.json`
- 第 4 步：图片理解
  - 输入：`cleaned/images/`
  - 输出：`stage/image_descriptions.json`
- 第 5 步：图片映射
  - 输入：`stage/with_placeholders.json`、`stage/image_descriptions.json`
  - 输出：`output/final_exam.json`
- 第 6 步：排版
  - 输入：`output/final_exam.json`
  - 输出：最终排版文档

**一、主 Skill 设计**
文件：`skills/master_exam_layout.md`

用途：只做流程调度与检查，不直接分析试卷内容。

建议内容：
```md
# Skill: master_exam_layout

## Role
你是试卷排版总控助手。你的职责是按固定流程调用子技能，检查每一步输出是否存在且格式正确，再进入下一步。

## Workflow
严格按以下顺序执行：
1. 调用 `clean_exam`
2. 检查是否生成 `cleaned/content.md` 和 `cleaned/images/`
3. 调用 `tag_structure`
4. 检查是否生成 `stage/structure.json`
5. 调用 `tag_placeholders`
6. 检查是否生成 `stage/with_placeholders.json`
7. 调用 `tag_images`
8. 检查是否生成 `stage/image_descriptions.json`
9. 调用 `map_images`
10. 检查是否生成 `output/final_exam.json`
11. 调用 `typeset_exam`

## Rules
- 不要跳步
- 不要把多个子任务合并成一次推理
- 如果某一步输出缺失、字段不完整或 JSON 非法，停止并报告错误
- 不直接修改脚本逻辑，除非用户要求
- 每一步都记录输入路径和输出路径

## Output
输出当前执行状态：
- current_step
- input_files
- output_files
- validation_result
- next_action
```

**二、清洗 Skill**
文件：`skills/clean_exam.md`

用途：只调用脚本，不做语义判断。

```md
# Skill: clean_exam

## Role
你负责调用试卷清洗脚本，对原始文档进行预处理，提取正文和图片资源。

## Input
- 原始试卷文件路径

## Required Actions
- 调用既有清洗脚本
- 生成清洗后的正文文件 `cleaned/content.md`
- 将图片单独存入 `cleaned/images/`

## Constraints
- 不分析题目结构
- 不判断标题、题干、材料
- 不修改正文语义，只做清洗、抽取、规范化

## Output Format
返回 JSON：
```json
{
  "step": "clean_exam",
  "source_file": "",
  "cleaned_text_file": "cleaned/content.md",
  "image_dir": "cleaned/images",
  "image_count": 0,
  "status": "success",
  "errors": []
}
```

## Validation
- `cleaned/content.md` 必须存在
- `cleaned/images/` 必须存在
- 如果没有图片，也要返回空目录和 `image_count=0`
```

**三、结构打标 Skill**
文件：`skills/tag_structure.md`

这是最关键的一步，但这里只做结构识别，不碰图片匹配。

```md
# Skill: tag_structure

## Role
你负责将清洗后的试卷正文识别为标准结构化 JSON。

## Input
- `cleaned/content.md`
- `templates/exam_reference.json`
- `schemas/exam_paper.schema.json`

## Task
根据正文内容识别并标注：
- 试卷标题
- 副标题
- 说明文字
- 大题/题组
- 题号
- 题干
- 选项
- 材料
- 小问

## Constraints
- 不处理图片文件
- 不创建图片映射
- 不臆造缺失内容
- 无法判断时标记 `uncertain: true`，并写入 `notes`

## Output
输出文件：`stage/structure.json`

## Output Rules
- 严格遵循 schema
- 保留原文文本
- 每个结构块都要有 `id`
- 每道题都要归属某个 section
- 未识别文本要放入 `unclassified_blocks`

## Self-check
生成前检查：
- 是否所有题号都进入 questions
- 是否所有选项都归属某道题
- 是否存在重复 id
- 是否存在未归类大段文本
```

**四、图片占位 Skill**
文件：`skills/tag_placeholders.md`

这里只判断“哪里需要图片”，不负责图片是谁。

```md
# Skill: tag_placeholders

## Role
你负责在结构化试卷 JSON 中标出需要插入图片的位置。

## Input
- `stage/structure.json`

## Task
根据题干、材料、上下文语义判断哪些位置需要图片。
在对应位置插入占位符，例如：
`{{image:ph_001}}`

## Constraints
- 不读取图片文件
- 不猜测具体图片文件名
- 仅创建占位符及上下文说明

## Output
输出文件：`stage/with_placeholders.json`

## Placeholder Rules
每个占位符需包含：
- `placeholder_id`
- `context_before`
- `context_after`
- `location_type` (`title`/`material`/`question_stem`/`subquestion`)
- `owner_id`
- `reason`

## Self-check
- 每个占位符必须能定位到一个结构节点
- 占位符 ID 不可重复
- 不得在无依据处插图
```

**五、图片理解 Skill**
文件：`skills/tag_images.md`

只理解图片，不回填位置。

```md
# Skill: tag_images

## Role
你负责逐张读取图片并生成语义描述。

## Input
- `cleaned/images/`

## Task
对每张图片进行内容理解，提取：
- 图片类型
- 主题
- 关键文字
- 关键对象
- 学科特征
- 与试题可能相关的线索

## Output
输出文件：`stage/image_descriptions.json`

## Output Format
```json
{
  "images": [
    {
      "image_id": "img_001",
      "file_name": "1.png",
      "type": "diagram",
      "summary": "一个电路连接图，含电源、开关和灯泡",
      "keywords": ["电路", "开关", "灯泡"],
      "ocr_text": [],
      "uncertain": false
    }
  ]
}
```

## Constraints
- 不决定图片放在哪
- 不修改试卷正文
- 不合并多张图片
```

**六、图片映射 Skill**
文件：`skills/map_images.md`

这里只做“占位符 ↔ 图片”匹配。

```md
# Skill: map_images

## Role
你负责根据占位符上下文和图片语义描述，完成图片与占位符的映射。

## Input
- `stage/with_placeholders.json`
- `stage/image_descriptions.json`

## Task
对每个占位符匹配最合适的图片，并写入最终 JSON。

## Matching Basis
综合以下信息判断：
- 占位符前后文
- 所属题目主题
- 材料语境
- 图片 summary
- 图片 keywords
- 图片中的 OCR 文字

## Constraints
- 一张图片默认只能映射一个占位符，除非明确可复用
- 无法确定时保留 `unmapped`
- 不得强行凑满映射

## Output
输出文件：`output/final_exam.json`

## Required Fields
- `placeholders`
- `images`
- `image_mapping`
- `unmapped_placeholders`
- `unused_images`

## Self-check
- 所有映射必须引用真实 `placeholder_id`
- 所有映射必须引用真实 `image_id`
- 输出必须可被 schema 校验
```

**七、排版 Skill**
文件：`skills/typeset_exam.md`

这里只调用脚本。

```md
# Skill: typeset_exam

## Role
你负责根据最终 JSON 调用排版脚本，生成目标文档。

## Input
- `output/final_exam.json`

## Task
- 检查 JSON 完整性
- 调用排版脚本
- 输出最终文件路径

## Constraints
- 不重新理解题目结构
- 不修改 JSON 语义
- 如果 JSON 缺字段，先报错，不强行排版

## Output Format
```json
{
  "step": "typeset_exam",
  "input_file": "output/final_exam.json",
  "output_file": "dist/final_exam.docx",
  "status": "success",
  "errors": []
}
```
```

**九、参考模板文件**
文件：`templates/exam_reference.json`

这个文件不要放真实试卷内容，而要放“标准组织范式”。例如：
- 标题一般在最前
- 大题下面有若干题
- 题目可能带材料
- 选择题有选项数组
- 图片位置用 placeholders 表示

也就是说，它是“格式样板”，不是“答案模板”。

**十、异常处理文档**
文件：`docs/error_cases.md`

你至少提前定义这些异常：
- 题号丢失或乱序
- OCR 把选项和题干粘连
- 多栏文本串行化
- 图文分离导致上下文错位
- 表格被拆成纯文本
- 一张图对应多个小问
- 图片文件名顺序与正文顺序不一致
- 没有图片但正文提到“如图所示”

每个异常要写：
- 现象
- 可能原因
- 哪一步处理
- 是否允许输出 `uncertain`

**十一、建议的开发顺序**
不要直接写全套，按下面顺序迭代：

- 第 1 轮：只打通清洗 → 结构打标
  - 先不处理图片
  - 目标是得到稳定 `structure.json`
- 第 2 轮：加入图片占位
  - 先只输出占位符，不做图片匹配
- 第 3 轮：加入图片理解
  - 先只产出 `image_descriptions.json`
- 第 4 轮：加入图片映射
  - 只做匹配，不做排版
- 第 5 轮：接排版脚本
  - 验证最终 JSON 是否足够支撑排版

**十二、测试方法**
建议准备 5 份样本，不要一上来用海量文档：
- 1 份纯文字试卷
- 1 份带少量图片试卷
- 1 份材料题较多试卷
- 1 份格式混乱试卷
- 1 份扫描/OCR 误差较大试卷

每一轮只验证一个目标：
- 结构识别准确率
- 占位合理性
- 图片描述质量
- 图片映射正确率
- 排版稳定性

**十三、你写 Prompt 时的关键技巧**
每个 Skill 都要有这 5 段：
- `Role`：你是谁
- `Input`：你读取什么
- `Task`：你只做什么
- `Constraints`：你绝对不能做什么
- `Output Format`：你必须怎么输出

这样可以大幅降低 AI 一口气“越界发挥”的概率。

**十四、最容易踩坑的点**
- 主 Skill 写得太聪明，结果它自己开始理解题目。
- 打标 Skill 同时做结构、占位、图片理解、映射，导致错误无法定位。
- 没有统一 schema，后续脚本无法稳定消费。
- 输出不落盘，只靠对话上下文串联。
- 缺少 `uncertain`、`warnings`、`unclassified_blocks` 这类兜底字段，导致 AI 硬猜。

**我建议你现在立刻开始的动作**
- 先把 `exam_paper.schema.json` 定下来
- 再写 `tag_structure.md`
- 拿 1 份最典型试卷试跑
- 先确认 `structure.json` 是否稳定
- 稳定后再继续图片链路
