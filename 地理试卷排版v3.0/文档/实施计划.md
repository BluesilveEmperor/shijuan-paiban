## 一、重构背景与现状分析

### 1.1 v2.0 架构现状

v2.0 采用"AI 主导编排"架构，通过 [SKILL.md](file:///c:/Users/Deledy_02/Desktop/GeoPaperFormat/地理试卷排版v2.0/SKILL.md) 的 `description` 字段自动触发子技能，形成"清洗→打标→排版"三阶段流水线：

```
geo-exam-formatting（主编排）
  ├─ geo-exam-clean（清洗阶段）
  │   ├─ clean_docx.py        清洗 docx
  │   ├─ extract_images.py    提取图片
  │   ├─ geo-exam-image-analysis   AI 图片理解
  │   └─ geo-exam-image-insertion  AI 插入占位符
  ├─ geo-exam-tag（打标阶段）
  │   ├─ tag_docx.py          正则打标
  │   ├─ geo-exam-ai-tagging       AI 语义打标
  │   └─ geo-exam-merge-validation 双轨融合验证
  └─ geo-exam-format（排版阶段）
      └─ format_docx.py       模板排版
```

**现有数据契约**：
- 清洗输出：`插入图片后.docx` + `images/` + `images_analysis.json` + `image_manifest.json`
- 打标输出：`tagged_script.json` + `tagged_ai.json` → `tagged_final.json`
- 排版输出：`formatted.docx` + `quality_report.html`
- 现有 Schema：见 [json_schema.json](file:///c:/Users/Deledy_02/Desktop/GeoPaperFormat/地理试卷排版v2.0/geo-exam-tag/ai-skills/geo-exam-ai-tagging/references/json_schema.json)，含 `exam_info` / `sections` / `question_groups` / `questions` / `confidence`

### 1.2 v2.0 核心问题诊断

经系统遍历 v2.0 全部 SKILL 与脚本，诊断出以下关键问题：

| 编号 | 问题 | 证据 | 影响 |
|------|------|------|------|
| P1 | **AI 打标过度聚合** | [geo-exam-ai-tagging/SKILL.md](file:///c:/Users/Deledy_02/Desktop/GeoPaperFormat/地理试卷排版v2.0/geo-exam-tag/ai-skills/geo-exam-ai-tagging/SKILL.md) 一次完成结构识别+图片占位识别+图片引用 | 错误无法定位，单点失败波及全链路 |
| P2 | **触发依赖 description 隐式约定** | [SKILL.md](file:///c:/Users/Deledy_02/Desktop/GeoPaperFormat/地理试卷排版v2.0/SKILL.md) L216-219 "子skills通过description自动触发" | 流程不稳定，依赖 AI 自觉，易跳步或漏步 |
| P3 | **图片占位符格式不统一** | 清洗用 `【图片：xxx - 描述】`，排版用 `{{IMAGE:xxx}}`，需三层向后兼容（见 [geo-exam-clean/SKILL.md](file:///c:/Users/Deledy_02/Desktop/GeoPaperFormat/地理试卷排版v2.0/geo-exam-clean/SKILL.md) L248-255） | 格式混乱，防御性代码冗余 |
| P4 | **双轨并行增加复杂度** | [validation_rules.md](file:///c:/Users/Deledy_02/Desktop/GeoPaperFormat/地理试卷排版v2.0/geo-exam-tag/ai-skills/geo-exam-merge-validation/references/validation_rules.md) 脚本轨+AI轨融合逻辑复杂 | 维护成本高，置信度判定模糊 |
| P5 | **Schema 与排版脚本耦合不彻底** | [format_docx.py](file:///c:/Users/Deledy_02/Desktop/GeoPaperFormat/地理试卷排版v2.0/geo-exam-format/scripts/format_docx.py) 同时支持格式A/B/旧字段三种图片表示 | 排版脚本需做语义判断，违背"纯样式应用"原则 |
| P6 | **兜底字段不系统** | Schema 仅有 `confidence`，缺 `uncertain` / `unclassified_blocks` / `warnings` 统一规范 | AI 倾向硬猜而非标注不确定 |
| P7 | **缺少占位符↔图片映射独立环节** | 图片理解(image-analysis)与图片插入(image-insertion)在清洗阶段完成，未与结构解耦 | 图文分离时上下文错位无法纠正 |

### 1.3 重构必要性

v2.0 已验证"清洗→打标→排版"主链路可行，但**单点聚合与隐式触发**导致：错误难定位、扩展难推进、结果不稳定。重构的核心不是推翻重写，而是**拆解聚合点、显式化契约、落盘化数据流**，使每一步可控、可验证、可回滚。

## 二、重构目标

### 2.1 总体目标

将 v2.0 的"三阶段聚合流水线"重构为"六步骤解耦流水线"，每一步只做一件事、有固定输入输出、结果落盘可校验，最终实现地理试卷排版的**稳定、可追溯、可扩展**。

### 2.2 具体目标

| 编号 | 目标 | 衡量标准 |
|------|------|----------|
| G1 | **流程解耦** | 6 个子 Skill 各司其职，单一职责，无跨步骤语义越界 |
| G2 | **契约显式化** | 每步有明确 JSON Schema 校验，输入输出落盘，不依赖上下文记忆 |
| G3 | **主编排纯调度** | 主 Skill 不理解试卷内容，只检查产物存在性与格式合法性 |
| G4 | **图片链路独立** | 占位、理解、映射三步分离，支持图文分离场景纠正 |
| G5 | **兜底字段系统化** | 统一 `uncertain` / `warnings` / `unclassified_blocks` / `unmapped` 规范 |
| G6 | **资产最大化复用** | v2.0 可复用脚本（clean_docx/extract_images/format_docx/template.dotx）直接迁移 |
| G7 | **可回滚** | 任一步骤失败可定位、可重跑该步骤而不影响前序产物 |

### 2.3 非目标（明确不做）

- 不重写已稳定的清洗脚本 `clean_docx.py`、`extract_images.py` 核心逻辑
- 不重写已验证的排版脚本 `format_docx.py` 排版规则与 `template.dotx` 模板样式
- 不引入新的编程语言或框架，仍基于 Python + python-docx
- 不追求全自动零人工，允许 `uncertain` 场景转人工确认
- 不在重构期间改动 v2.0 目录（v2.0 作为对照基线保留）

## 三、技术路线

### 3.1 设计原则

1. **Schema 先行**：先定 `exam_paper.schema.json`，再写各 Skill 的 Prompt
2. **单一职责**：每个子 Skill 只做一件事，Role/Input/Task/Constraints/Output 五段式定义
3. **落盘传递**：步骤间只通过文件传递数据，不依赖对话上下文
4. **可校验**：每步输出必须能被 Schema 或脚本校验
5. **不越界**：主 Skill 不理解内容，打标 Skill 不碰图片匹配，图片 Skill 不改正文
6. **兜底优先**：无法确定时标注 `uncertain: true`，不硬猜

### 3.2 架构设计：六步解耦流水线

```
原始试卷.docx
    │
    ▼
[Step1] clean_exam ──────────► cleaned/content.md + cleaned/images/
    │
    ▼
[Step2] tag_structure ───────► stage/structure.json
    │
    ▼
[Step3] tag_placeholders ────► stage/with_placeholders.json
    │
    ▼
[Step4] tag_images ──────────► stage/image_descriptions.json
    │                              (并行于 Step2/3，仅依赖 cleaned/images/)
    ▼
[Step5] map_images ──────────► output/final_exam.json
    │
    ▼
[Step6] typeset_exam ────────► dist/final_exam.docx
```

**与 v2.0 的关键差异**：
- v2.0 的 `ai-tagging`（聚合结构+占位+图片）→ 拆为 Step2/3/4/5
- v2.0 的 `image-analysis`+`image-insertion`（清洗阶段内嵌）→ 独立为 Step4/5，与结构解耦
- v2.0 的 `merge-validation`（双轨融合）→ 取消双轨，改为单轨 + Schema 校验 + 兜底字段
- v2.0 的隐式 description 触发 → 改为主 Skill 显式编排 + 产物检查

### 3.3 数据契约设计

#### 3.3.1 统一 JSON Schema（`schemas/exam_paper.schema.json`）

基于重构方案第八节骨架，融合 v2.0 [json_schema.json](file:///c:/Users/Deledy_02/Desktop/GeoPaperFormat/地理试卷排版v2.0/geo-exam-tag/ai-skills/geo-exam-ai-tagging/references/json_schema.json) 已验证字段，核心结构：

```json
{
  "meta": { "title", "subject", "grade", "source_file" },
  "document": {
    "sections": [{
      "id", "type", "title", "instructions": [],
      "questions": [{
        "id", "number", "stem",
        "materials": [{ "id", "content" }],
        "subquestions": [{ "id", "label", "stem" }],
        "options": [{ "label", "text" }],
        "placeholders": [{ "placeholder_id", "token", "location_type",
                           "owner_id", "context_before", "context_after", "reason" }]
      }]
    }],
    "unclassified_blocks": []
  },
  "images": [{ "image_id", "file_name", "type", "summary",
               "keywords": [], "ocr_text": [], "uncertain": false }],
  "image_mapping": [{ "placeholder_id", "image_id", "confidence", "reason" }],
  "validation": { "has_unmapped_placeholders", "has_unused_images", "warnings": [] }
}
```

**与 v2.0 Schema 的字段映射与演进**：

| v2.0 字段 | v3.0 字段 | 演进说明 |
|-----------|-----------|----------|
| `exam_info.exam_name` | `meta.title` | 重命名，语义更通用 |
| `sections[].question_groups` | `document.sections[].questions` | 扁平化，题组概念融入 section |
| `materials[].images` | `placeholders[]` + `image_mapping` | 图片引用从内嵌改为占位符+映射分离 |
| `options: {A,B,C,D}` | `options: [{label,text}]` | 改为数组，支持灵活选项数 |
| `sub_questions` | `subquestions` | 统一命名 |
| `confidence` | `image_mapping[].confidence` + `validation.warnings` | 置信度下沉到映射层 |
| （无） | `uncertain` / `unclassified_blocks` | 新增系统化兜底字段 |
| `stem_images` | `placeholders[location_type="question_stem"]` | 题干图片纳入统一占位符体系 |

#### 3.3.2 占位符格式统一

- **v3.0 统一格式**：`{{image:ph_001}}`（占位符 ID 引用，不含文件名）
- **映射层**：`image_mapping` 数组建立 `placeholder_id ↔ image_id` 关系
- **排版层**：`format_docx.py` 读取映射后插入真实图片
- **v2.0 兼容**：迁移时保留对 `{{IMAGE:xxx}}` 的识别作为过渡，最终废弃

### 3.4 技术选型

| 层面 | 选型 | 说明 |
|------|------|------|
| 脚本语言 | Python 3.8+ | 沿用 v2.0 |
| 文档处理 | python-docx 1.2.0 + lxml 6.0.4 | 沿用 v2.0 已验证版本 |
| 模板 | template.dotx（21种样式） | 直接迁移 v2.0 资产 |
| Schema 校验 | jsonschema（Python 库） | 新增，用于每步产物校验 |
| 中间格式 | JSON（UTF-8） | 所有步骤间传递 |
| 清洗正文格式 | Markdown（content.md） | 便于 AI 读取理解，区别于 v2.0 的 docx |

## 五、实施步骤（分阶段）

遵循重构方案第十一节"建议的开发顺序"，分 6 个阶段迭代，每阶段只验证一个目标。

### 阶段 0：基础设施搭建

**目标**：搭好骨架，定下契约，为后续所有步骤提供校验基础。

**输入**：重构方案.md、v2.0 现状分析

**输出**：
- `schemas/exam_paper.schema.json`（统一 Schema）
- `scripts/validate_json.py`（校验工具）
- `templates/exam_reference.json`（格式样板）
- v3.0 完整目录结构

**任务清单**：
1. 创建 v3.0 目录结构（skills/schemas/templates/scripts/assets/docs/tests/runtime）
2. 编写 `exam_paper.schema.json`（基于 3.3.1 节设计，含完整字段定义、类型约束、required 列表）
3. 编写 `validate_json.py`（读取 schema + json 文件，输出校验结果 JSON）
4. 编写 `exam_reference.json`（放"标准组织范式"：标题在前、大题下有题、选择题有 options 数组、图片位置用 placeholders 表示，不含真实试卷内容）
5. 迁移 v2.0 脚本与模板到 v3.0 对应目录
6. 编写 `docs/pipeline.md`（六步流水线说明）

**验证标准**：
- `validate_json.py` 能对一个合法 JSON 返回 `valid: true`，对非法 JSON 返回 `valid: false` + 错误明细
- `exam_reference.json` 自身能通过 Schema 校验
- 目录结构与 4.1 节一致

**风险**：Schema 设计不当导致后续步骤频繁返工 → 缓解：参考 v2.0 已验证字段，先跑通 1 份样本再固化

---

### 阶段 1：清洗 → 结构打标（先不碰图片）

**目标**：打通 Step1→Step2，得到稳定的 `structure.json`，不处理任何图片。

**输入**：1 份纯文字试卷 + 1 份带少量图片试卷

**输出**：
- `skills/clean_exam.md`
- `skills/tag_structure.md`
- `runtime/cleaned/content.md` + `runtime/cleaned/images/`
- `runtime/stage/structure.json`

**任务清单**：

*Step1 清洗*：
1. 编写 `clean_exam.md`（Role/Input/Task/Constraints/Output 五段式）
   - 调用迁移后的 `clean_docx.py` 生成清洗 docx
   - 调用 `extract_images.py` 提取图片到 `cleaned/images/`
   - **新增**：将清洗后 docx 转为 `content.md`（Markdown，便于 AI 读取）
   - 不分析题目结构、不判断标题题干
2. 微调 `extract_images.py` 输出路径为 `cleaned/images/`
3. 编写 docx→md 转换逻辑（可内置 utils.py 或新增 to_md.py，**但遵守 v2.0"AI 不自写脚本"约束时由人工提供**）

*Step2 结构打标*：
4. 编写 `tag_structure.md`（五段式）
   - 输入：`content.md` + `exam_reference.json` + `exam_paper.schema.json`
   - 识别：试卷标题、副标题、说明文字、大题/题组、题号、题干、选项、材料、小问
   - 不处理图片、不创建图片映射
   - 无法判断时标记 `uncertain: true` 并写入 `notes`
5. 用 `validate_json.py` 校验 `structure.json` 合法性

**验证标准**：
- 纯文字试卷的 `structure.json` 题号识别准确率 ≥ 95%
- 选项全部归属某道题
- 无重复 id
- 未识别文本进入 `unclassified_blocks`
- `structure.json` 通过 Schema 校验

**风险**：docx→md 转换丢失结构信息 → 缓解：保留段落分隔与题号格式，转换规则需人工确认

---

### 阶段 2：加入图片占位

**目标**：在 `structure.json` 基础上标出需要图片的位置，只输出占位符，不做图片匹配。

**输入**：阶段 1 产出的 `structure.json` + 带少量图片试卷

**输出**：
- `skills/tag_placeholders.md`
- `runtime/stage/with_placeholders.json`

**任务清单**：
1. 编写 `tag_placeholders.md`（五段式）
   - 输入：`stage/structure.json`

##### 5.4.2 混合字体引擎

- **字符分类**：ASCII 字母/数字 → `'en'`（Times New Roman）；ASCII 单引号（经纬度）→ `'en'`；Unicode 上/下标 → `'en'`；其余 → `'cn'`

## 七、质量标准

### 7.1 代码质量

- 脚本必须能独立运行，通过命令行参数接收输入输出路径
- 所有脚本支持 `--log` 参数记录运行日志
- 函数单一职责，核心逻辑有注释（仅解释 WHY，不解释 WHAT）
- 异常情况返回非零退出码并写入日志，不静默失败
- 遵守 v2.0 既有约束："AI 不自写脚本，只调用已有脚本"

### 7.2 Schema 质量

- 使用 JSON Schema Draft-07
- 所有对象定义 `required` 字段
- 枚举值用 `enum` 约束（如 `location_type`、`section_type`）
- 字符串字段说明 `description`
- 兜底字段（`uncertain` / `unclassified_blocks` / `warnings` / `unmapped`）必须存在
- Schema 自身可通过 `validate_json.py` 自校验

### 7.3 Skill Prompt 质量

每个 Skill 必须包含五段：
- `Role`：你是谁（单一职责）
- `Input`：你读取什么（明确文件路径）
- `Task`：你只做什么（不越界）
- `Constraints`：你绝对不能做什么（负面清单）
- `Output Format`：你必须怎么输出（JSON 格式 + 落盘路径）

质量检查：
- 无模糊表述（如"尽量"、"适当"）
- Constraints 覆盖常见越界场景
- Output Format 给出字段示例

### 7.4 输出质量

| 产物 | 质量标准 |
|------|----------|
| `content.md` | 段落完整、题号保留、无水印残留 |
| `structure.json` | 题号识别率 ≥ 95%、无重复 id、通过 Schema 校验 |
| `with_placeholders.json` | 占位符有 owner_id 和 reason、ID 唯一 |
| `image_descriptions.json` | 每图有 summary 和 keywords、image_count 一致 |
| `final_exam.json` | 映射正确率 ≥ 90%、通过 Schema 校验、validation 字段完整 |
| `final_exam.docx` | 可被 Word 打开、图片位置正确、样式符合模板 |

## 十、异常处理手册（error_cases.md 预定义）

依据重构方案第十节，至少预定义以下 8 类异常，每类含：现象、可能原因、处理步骤、是否允许 `uncertain`。
