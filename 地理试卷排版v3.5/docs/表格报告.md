## 一、表格处理全链路概览

表格从原始 Word 到最终排版文档，经过以下阶段：

```
原始 docx
  ↓
[clean_docx.py] 清洗：保留表格结构不变
  ↓
[extract_images.py] 提取图片：递归提取表格内图片（BUG-06 已修复）
  ↓
[utils.py::docx_to_markdown()] Docx → Markdown + tables.json：
    - Markdown 中插入 {{table:table_NNN}} 占位符
    - tables.json 输出结构化表格数据（rows/cols/data/spans）
  ↓
[AI: tag_structure] 结构标注：
    - 从 tables.json 读取表格数据
    - 将表格作为 material segments 中的 type: "table" 条目
  ↓
[typeset_exam.py::add_table()] 排版生成：
    - 创建 python-docx 表格
    - 设置 Table Grid 样式
    - 首行黑体加粗 + 宋体正文
    - 应用单元格合并
    - 设置跨页表头
```

## 四、已发现的问题（6 个）

### 问题 1：`has_header` 默认 `True`，数据链路断裂（P1 - 严重）

**代码位置**：[typeset_exam.py:423](file:///c:/Users/Deledy/Desktop/GeoPaperFormat/地理试卷排版v3.5/scripts/typeset_exam.py#L423)

```python
has_header = table_data.get('has_header', True)  # 默认 True
```

**数据流断裂证明**：

1. `_table_to_data()` 的输出结构只有 `{rows, cols, data, spans}`，**不包含 `has_header`**
2. `tables.json` 由该方法生成，因此永远不会有 `has_header: false`
3. `tag_structure` 技能的 SKILL.md **从未提及 `has_header` 字段**
4. 因此 `table_data.get('has_header', True)` 的默认值 `True` **永远生效**

**受影响的场景**：

- 纯排版/布局表格（无表头概念）
- 所有行都是数据行的表格
- 用表格做对齐的格式表格（如选项排列）

---

### 问题 2：表格内图片无法渲染（P1 - 严重）

**代码位置**：[typeset_exam.py:414-429](file:///c:/Users/Deledy/Desktop/GeoPaperFormat/地理试卷排版v3.5/scripts/typeset_exam.py#L414-L429)

`add_table()` 将单元格内容作为纯文本处理，**不检测 `{{image:img_xxx}}` 占位符**。

**三层断裂**：

| 层级 | 问题 | 状态 |
|---|---|---|
| 提取端 | `extract_images.py` 不递归查找表格内图片 | BUG-06，已修复 |
| 数据转换端 | `_extract_cell_text()` 只提取 `w:t` 纯文本，图片 run 被忽略 | 未修复 |
| 排版端 | `add_table()` 不处理 `{{image:...}}` 占位符 | 未修复 |

---

### 问题 3：`{{symbol}}` 标记未处理（P2 - 中）

与问题 2 同源。`add_table()` 不识别任何占位符，包括 `{{symbol:img_xxx}}`（小符号图片残留）。

---

### 问题 4：合并信息与样式顺序冲突（P2 - 中）

**代码位置**：[typeset_exam.py:431-442](file:///c:/Users/Deledy/Desktop/GeoPaperFormat/地理试卷排版v3.5/scripts/typeset_exam.py#L431-L442)

文本填充和样式设置（L414-429）早于单元格合并（L431-442）。当有纵向合并（rowspan > 1）时，被合并单元格在下方行仍有残留文本和样式：

```
414-429: 填充所有单元格文本 + 设置样式（首行黑体/非首行宋体）
431-442: 执行单元格合并（合并后，被合并位置仍有残留样式）
```

---

### 问题 5：Schema 中 table segment 字段缺失（P2 - 中）

`schemas/exam_paper.schema.json` 中 `table` 类型 segment 只定义了 `type` 枚举，但实际运行时 `tag_structure` 会输出 `data` 字段，而 `add_table()` 会读取 `has_header`。这些字段均未在 Schema 中定义。

---

### 问题 6：排版顺序僵化（P3 - 低）

**代码位置**：[typeset_exam.py:886](file:///c:/Users/Deledy/Desktop/GeoPaperFormat/地理试卷排版v3.5/scripts/typeset_exam.py#L886)

```
排版顺序：{材料内容(楷体)}{引导语(宋体)} → {图片} → {表格}
```

选择题中图片**始终**在表格前渲染。无法满足"表格在上、图片在下"的场景。

## 六、修复建议

### 短期（紧急）

| 优先级 | 修复项 | 方案 |
|---|---|---|
| P1 | 打通 `has_header` 数据链路 | `_table_to_data()` 增加 `has_header` 输出；`tag_structure` 技能增加判断规则；或使用启发式自动判断 |
| P1 | `add_table()` 支持占位符检测 | 单元格渲染循环中加入 `PLACEHOLDER_TOKEN_PATTERN.split()` 处理 |

### 中期

| 优先级 | 修复项 | 方案 |
|---|---|---|
| P2 | `_extract_cell_text()` 记录图片 run 位置 | 在单元格数据中标记图片占位符位置 |
| P2 | 表格样式柔性化 | 支持 `table_style`（有/无网格）、`col_widths`（列宽比）、`header_rows`（多行表头） |
| P2 | Schema 补全 | 将 `data`、`has_header`、`name` 等实际字段加入 Schema |

### 长期

| 优先级 | 修复项 | 方案 |
|---|---|---|
| P3 | 排版顺序可控 | 增加 `display_order` 字段，允许指定"表格优先" |
| P3 | 单元格级别字体控制 | 扩展 `data` 为 `[{text, font}]` 结构化单元格数据 |
| P3 | 页面宽度自适应列宽 | 根据单元格内容长度动态分配列宽比例 |
