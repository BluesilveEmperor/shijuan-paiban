# v3.5 排版问题分析报告

> 基于用户反馈的 6 个排版问题，逐一分析根因和修复方案

---

## 问题 1: 选择题材料中图片标记残留

**现象**: `img_004`、`img_005` 等图片标记作为文本残留在材料中，没有被替换为实际图片。

**示例**:
```
图 4 为波尔蒂芒位置示意图。img_004据此完成 6-8 题。
```

**根因**: 修复 BUG-02 时给 `PLACEHOLDER_TOKEN_PATTERN` 添加了捕获组 `()`。这改变了 `re.split()` 的返回值结构：

| 版本 | 正则 | `split("abc{{image:img_001}}def")` 结果 |
|------|------|----------------------------------------|
| 修复前 | `r'\{\{image:ph_\d{3}\}\}'` (无捕获组) | `["abc", "def"]` — 分隔符被丢弃 |
| 修复后 | `r'\{\{image:(ph(?:_anchor)?_\d{3}\|img_\d{3})\}\}'` (有捕获组) | `["abc", "img_001", "def"]` — 奇数索引是捕获组内容 |

`_format_choice_material_with_images` 函数用 `''.join(text_parts)` 拼接所有文本，把占位符 ID（如 `img_001`）也当文本拼了进去。

**已修复**: 改为 `''.join(text_parts[i] for i in range(0, len(text_parts), 2))` 只取偶数索引（纯文本）。

## 问题 2: 主观题图片后残留标记

**现象**: 主观题材料中，`【图片】` 后出现 `img_007`、`img_008` 等文字。

**示例**:
```
【图片】
img_007
```

**根因**: 与问题 1 同根同源。`_format_materials_inner` 中主观题分支也用 `enumerate(text_parts)` 遍历，但没区分奇偶索引。捕获组改变 `split` 返回值后，奇数索引的占位符 ID 被当作文本传给 `add_mixed_text()`，原样输出到文档。

**已修复**: 主观题分支改为 `if k % 2 == 0:` / `else:` 区分文本和占位符。所有使用 `PLACEHOLDER_TOKEN_PATTERN.split()` 的位置（共 6 处）已统一修改为奇偶索引模式。

---

## 问题 3: 材料被图片标记掐断，字体混乱

**现象**: 一段本应统一为楷体的材料，在图片标记处被强行分割，前半段楷体、后半段宋体。

**示例**:
```
楷体：东兰墨米耐阴凉...（如下图）。
img_002  ← 残留标记
宋体：近年来...据此完成 3~4 题。
```

**根因**: 这是问题 1+2 的连锁效应。代码本应在 `{{image:img_002}}` 处替换为图片，但由于捕获组问题，`img_002` 被当作文本输出。更关键的是：

1. 主观题材料渲染时，每个文本片段创建一个新段落（`doc.add_paragraph()`）
2. 图片标记把一段连续材料切成了 2 个段落
3. 引导语（guide_sentence）被附加到最后一个段落后，使用的是宋体而非楷体
4. 这就导致了"前半段楷体、后半段宋体"的视觉错误

**已修复**: 所有 `split` 遍历位置已改为奇偶索引模式，图片标记不再被当作文本，不会切分段落。

**用户追问**: "是否是正则表达式出现了问题，导致这里的材料被强行掐断？"——**是的**，正则捕获组改变 `split` 返回值结构是直接原因。

"案例是这部分打标操作应该是纯 AI 驱动的，为何还是出现了这样的问题？"——**排版脚本是纯代码驱动的**，不受 AI 影响。问题出在代码层面（正则+split 的交互），而非 AI 打标步骤。

## 问题 4: 表格第一行被机械设为表头

**现象**: 所有表格的第一行都被格式化为黑体加粗的表头样式，但实际业务中并非所有表格都有表头。

**根因**: `add_table()` 函数硬编码 `if i == 0:` 将第一行设为黑体加粗，没有从数据结构中读取是否有表头的信息。

**已修复**: 改为 `if has_header and i == 0:`，其中 `has_header` 从 `table_data.get('has_header', True)` 读取。默认为 True（保持兼容），但 AI 打标时可在 table 数据中设置 `"has_header": false` 来禁用表头样式。

**后续建议**: `tag_structure` 技能应在生成表格数据时判断是否为表头行（通常：表头行单元格短、为分类标签；数据行单元格长、含具体数值），并写入 `has_header` 字段。

## 问题 5: 表格中的图片没有正确排入

**现象**: 表格中包含的图片无法正确渲染到最终文档中。

**根因分析**（两层问题）:

**层 1 — 提取端**: `extract_images.py` 之前用 `body.findall(qn('w:p'))` 非递归查找，表格内段落 `w:tbl > w:tr > w:tc > w:p` 无法被捕获。**已在上一轮修复为 `body.findall(f'.//{qn("w:p")}')`**。

**层 2 — 排版端**: `add_table()` 函数只处理 `cell_str = str(cell_text)`，即纯文本单元格。如果 `structure.json` 中表格的 data 数组含有图片标记（如 `{{image:img_xxx}}`），`add_mixed_text()` 会将标记原样输出为文字，不会替换为图片。

**修复方案**: `add_table()` 需要像其他排版函数一样，检测单元格文本中的 `{{image:...}}` 占位符并插入图片。这需要在单元格渲染逻辑中加入 `PLACEHOLDER_TOKEN_PATTERN.split()` 处理。

**优先级**: P2（中期改进），因需修改 `add_table()` 函数的单元格渲染逻辑，且涉及 `tag_structure` 技能需在表格 data 中标记图片位置。

## 问题 6: 小图片被当作内容图片

**现象**: 源文档中的标点符号图片（如句号、顿号等小图片，通常 < 2KB）被程序当作试卷内容图片处理，不断询问其内容和位置。

**根因分析**:

v3.5 的处理链路：

1. **`clean_docx.py` rule_1_18**（图片文字替换）: 已有逻辑处理 < 2KB 的小图片——WMF/EMF 直接提取文本，PNG/JPG 上下文推断。推断成功的替换为文字，失败的加入 `pending_images.json`。

2. **`extract_images.py`**: 提取所有图片（包括小图片），在 `image_manifest.json` 中记录。

3. **`map_images.py`**: `classify_images_by_original_type()` 中 `file_size < SYMBOL_SIZE_THRESHOLD (2048)` 的图片被分类为 `symbol_images`，不进入 `image_mapping`。

4. **`typeset_exam.py`**: 小图片没有 `image_mapping` 条目，但 `structure.json`/`content.md` 中仍有 `{{image:img_xxx}}` 标记指向它。`ImageResolver` 找不到映射就报告 `[图片:img_xxx]`。

**问题链路**:
```
clean_docx rule_1_18 尝试替换小图片
  → 成功：图片被替换为文字 ✓
  → 失败：图片保留，进入 extract_images → 进入 structure.json 中的 {{image:img_xxx}}
     → map_images 不映射它（正确行为）
     → typeset_exam 找不到映射 → 残留 [图片:img_xxx] 文本 ✗
```

**修复方案**（推荐，两步）:

**步 A**: 在 `map_images.py` 中，对 symbol_images 生成一个 "空映射" —— 将 `placeholder_id` 映射到自身，但在 `image_mapping` 中标记 `"track": "symbol"` 和 `"skip": true`。

**步 B**: 在 `typeset_exam.py` 的 `ImageResolver` 中，遇到 `track == "symbol"` 的映射时不插入图片，而是静默跳过（或插入推断的文字）。`_add_option_label_text` 等位置遇到未映射的占位符时，不输出 `[图片:xxx]` 文本，而是跳过。

**v3.0 参考方案**: v3.0 的 `clean_docx.py` rule_1_18 已经做了图片→文字替换。如果该步骤完全成功，小图片就不会出现在后续流程中。当前问题是 rule_1_18 的上下文推断成功率不是 100%，推断失败的小图片就成了"悬空"标记。

**优先级**: P1（高），建议尽快实现步 B（排版端静默跳过未映射的 symbol 标记），步 A 可后续跟进。
