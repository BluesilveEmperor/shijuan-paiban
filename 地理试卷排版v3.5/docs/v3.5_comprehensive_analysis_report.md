## 一、执行摘要

地理试卷排版系统 v3.5 采用"六步解耦流水线 + 代码/AI 双轨分流"架构，设计思路优秀，但在**执行层面存在严重缺陷**。核心问题集中在三个维度：

1. **图片全链路断裂**（最严重）：从占位符提取 → 映射 → 渲染的整条数据链存在多处断裂，导致最终文档**缺失全部图片**（实测 9 张图片全部丢失），对地理试卷而言是致命质量问题。根因是 [typeset_exam.py:61](file:///c:/Users/Deledy/Desktop/GeoPaperFormat/地理试卷排版v3.5/scripts/typeset_exam.py#L61) 的正则 `ph_\d{3}` 不匹配内嵌图片 ID `img_xxx`。
2. **目录内遗留文件干扰**：v3.5 目录内仍保留 v3.0 时代的旧技能文件（`tag_placeholders`、`tag_images`）和标注为 v3.0/v3.6 的文档，虽不会出现"多版本并存运行"，但旧技能的矛盾指令仍可能被 AI 误调用，应清理。
3. **Schema 契约失效**：`tag_placeholders_anchor` 技能违反 Schema 定义（`ph_anchor_001` 格式不匹配 `^ph_\d{3}$`、`_source`/`_ai_reason` 字段违反 `additionalProperties: false`），导致包含 anchor 图的试卷 Schema 校验失败。

**最紧急的 3 个问题**：
- 修复 `typeset_exam.py` 占位符正则不匹配问题（`ph_\d{3}` vs `img_xxx`），这是图片丢失的直接技术原因
- 修复 `structure.json` 解析器，从 `materials.content` 中提取图片占位符
- 修复 `tag_placeholders_anchor` 的 Schema 违反（`ph_anchor_001` 格式和 `_source` 字段）

## 二、项目概述

### 2.1 架构设计

系统采用六步流水线架构：

```
原始 docx → [Step1: clean_docx] → [Step2: tag_structure] → [Step3: tag_placeholders_anchor]
         → [Step4: tag_images_anchor] → [Step5: map_images] → [Step6: typeset_exam] → final docx
```

v3.5 核心改进：**双轨分流**
- inline 图：由代码确定性处理（零 AI）
- anchor 图：由 AI 介入处理

### 8.2 复核中发现的新情况

#### 8.2.1 BUG-02 是图片丢失的"第二道闸门"

原报告将 BUG-03 列为图片丢失的唯一直接原因，但实测发现 **BUG-02 同样致命**：

```python
# typeset_exam.py:61
PLACEHOLDER_TOKEN_PATTERN = re.compile(r'\{\{image:ph_\d{3}\}\}')  # 无捕获组 ()

# typeset_exam.py:498
parts = PLACEHOLDER_TOKEN_PATTERN.split(text)  # 无捕获组 → 分隔符被丢弃
for i, part in enumerate(parts):
    if i % 2 == 0:       # 恒为真（parts 全是文本）
        ...              # 永远走文本分支
    else:                # 永远不会进入图片插入分支
        ...              # 图片永远丢失
```

**含义**：即使把 BUG-03 的正则改为 `\{\{image:(ph|img)_\d{3}\}\}`，只要不加捕获组 `()`，图片仍会丢失。两个 BUG 必须同时修复。
