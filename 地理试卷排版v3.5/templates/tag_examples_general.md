## 案例1：表格表头判断 — 总原则

### 判断流程（两步走）

**第1步：先看整张表是干嘛用的。** 地理试卷中表格主要有四种用途：

| 用途 | 特征 | 一句话描述 |
|------|------|-----------|
| **数据展示** | 上方是列名，下方是数据值 | "这张表在展示一组统计数据" |
| **访谈/调查** | 每行独立，行与行是并列的"标签: 内容"关系 | "这张表是问卷或者调查记录" |
| **纯排版** | 表格只是用来分栏排文字的工具 | "这张表就是几段话并排放在一起" |
| **分不清** | 说不清是哪种 | 就当没表头 |

**第2步：只有"数据展示"表才可能有表头。** 其他三类 header_rows = 0。

## 案例1A：数据展示表 — 一层表头（header_rows = 1）

### 示例1："时期 | 主要抬升区"（简单两列）

```
tables.json:
{
  "rows": 4, "cols": 2,
  "data": [
    ["时期", "主要抬升区"],
    ["古新世—早始新世", "阿尔金山北支、东昆仑山"],
    ["中始新世—早渐新世", "阿尔金山南支"],
    ["早渐新世—中渐新世", "东昆仑山"]
  ]
}
```

→ **分析**：行0是列名标签，行1-3是具体数据。"时期"定义了第一列的含义，"主要抬升区"定义了第二列的含义。

→ **标注**：`header_rows: 1`

### 示例2："土层 | 土质 | 分层厚度 | 颜色 | 结构 | 根系"（多列表）

```
{
  "rows": 4, "cols": 6,
  "data": [
    ["土层", "土质", "分层厚度", "颜色", "结构", "根系"],
    ["耕作层", "壤质黏土", "0-20cm", "暗灰色", "碎屑状", "多"],
    ["黑土层", "黏土", "20-50cm", "暗黑色", "棱块状", "较多"],
    ["砂姜层", "壤质黏土", "50-100cm", "棕灰色", "块状", "少"]
  ]
}
```

→ **分析**：行0每列定义了一种属性名，行1-3每一行是一个土层的具体数据。

→ **标注**：`header_rows: 1`

### 示例3："指标 | 中国 | 美国"（对比表，首列也是标签）

```
{
  "rows": 5, "cols": 3,
  "data": [
    ["指标", "中国", "美国"],
    ["出口总额", "3.75万亿美元", "2.19万亿美元"],
    ["进口总额", "2.57万亿美元", "3.51万亿美元"],
    ["贸易差额", "顺差1.18万亿美元", "逆差1.32万亿美元"],
    ["主要出口产品", "机电产品、高技术产品...", "农产品、能源、航空航天..."]
  ]
}
```

→ **分析**：行0是列标签（指标 | 中国 | 美国）。行1-4首列"出口总额""进口总额"等也是标签，但这是列方向的标签，不影响 header_rows。

→ **标注**：`header_rows: 1`

### 示例4："比较维度 | 景德镇 | 德化"（对比表）

```
{
  "rows": 5, "cols": 3,
  "data": [
    ["比较维度", "景德镇", "德化"],
    ["主导产品", "艺术瓷、高端陈设瓷、文创产品", "日用瓷（茶具、餐具）、西洋工艺瓷"],
    ["生产方式", "手工拉坯、手绘为主，个性化强", "机器注浆、贴花为主，批量化大"],
    ["原料来源", "大量依赖外地（包括德化）输入", "本地及周边供应充足"],
    ["市场导向", "国内高端收藏、文旅体验、小众定制", "国际大众消费、国内电商批发"]
  ]
}
```

→ **分析**：同上。行0定义了三列分别是什么。

→ **标注**：`header_rows: 1`

### 示例5："国家 | 科威特 | 新西兰 | 美国 | …"（横向表头）

```
{
  "rows": 2, "cols": 8,
  "data": [
    ["国家", "科威特", "新西兰", "美国", "爱尔兰", "德国", "中国", "世界平均"],
    ["单产（吨/公顷）", "51.9", "50.8", "49.1", "45.6", "43.8", "16.3", "20.7"]
  ]
}
```

→ **分析**：行0是列标签（国家名），行1第一列"单产"是行标签。虽然首列也有标签，但 header_rows 只统计行方向的表头（顶部几行），这里只有行0是列标签。

→ **标注**：`header_rows: 1`

### 示例6："年份 | 出生率 | 死亡率 | …"（左右两半拼一起的表）

```
{
  "rows": 6, "cols": 8,
  "data": [
    ["年份", "出生率", "死亡率", "自然增长率", "年份", "出生率", "死亡率", "自然增长率"],
    ["1981", "20.91", "6.36", "14.55", "2021", "7.52", "7.18", "0.34"],
    ["1982", "22.28", "6.6", "15.68", "2022", "6.77", "7.37", "-0.6"],
    ...
  ]
}
```

→ **分析**：本质上是把两个四年段的数据左右并排，行0定义了两组同样的列名。

→ **标注**：`header_rows: 1`

## 案例1B：数据展示表 — 两层表头（header_rows = 2）

### 示例7：铌矿进口数据（第一层大分类，第二层子分类）

```
{
  "rows": 5, "cols": 5,
  "data": [
    ["时间", "我国铌矿主要进口国及占比", "", "", "对外依存度"],
    ["时间", "巴西", "加拿大", "其他", "对外依存度"],
    ["2022年", "98.50%", "1.20%", "0.30%", "98.07%"],
    ["2023年", "86.20%", "10.50%", "3.30%", "97.91%"],
    ["2024年", "78.10%", "15.60%", "6.30%", "97.75%"]
  ],
  "spans": [
    {"row": 0, "col": 0, "rowspan": 2, "colspan": 1},
    {"row": 0, "col": 1, "rowspan": 1, "colspan": 3},
    {"row": 0, "col": 4, "rowspan": 2, "colspan": 1}
  ]
}
```

→ **分析**：行0的"我国铌矿主要进口国及占比"是一个大分类标签（跨3列），行1的"巴西、加拿大、其他"是对应的子分类。行0的"时间"和"对外依存度"跨2行合并。前两行共同构成完整的列标签体系，行2才开始是数据。

→ **标注**：`header_rows: 2`

## 案例1C：访谈/调查表 — 没有表头（header_rows = 0）

### 示例9：访谈调查表

```
{
  "rows": 6, "cols": 2,
  "data": [
    [""景德镇产业发展对人才集聚的影响"访谈调查表", ""],
    ["访谈问题", "调查目的"],
    [""请问您当初选择来到景德镇...最主要原因是什么？"", "①"],
    ["②", "探究完善的产业协作配套..."],
    [""您认为景德镇城市产业转型...是否有利于您长期在此进行艺术创作？"", "调查城市产业转型..."],
    ["……", "……"]
  ],
  "spans": [
    {"row": 0, "col": 0, "rowspan": 1, "colspan": 2}
  ]
}
```

→ **分析**：行0是整个表的标题（合并）。行1写的是"访谈问题 | 调查目的"——看起来像列名，但行2-5的每一行是一条独立的访谈问答，行与行之间是并列关系，不存在"上行给下行下定义"的数据表结构。

→ **标注**：`header_rows: 0`（这是表单结构，不是数据表）

### 示例10：调查设计表

```
{
  "rows": 6, "cols": 2,
  "data": [
    ["调查目标", "在不同交通方式的帮助下，东湖绿道能否满足武汉市民的休闲需求"],
    ["调查对象", "绿道交通设施、居民及管理者"],
    ["调查方法", "①______________________________"],
    ["调查内容", "②______________________________"],
    ["数据处理", "应用GIS等工具，通过数据处理..."],
    ["结果分析", "根据调查结果，回答调查目标中的问题..."]
  ]
}
```

→ **分析**：每行是独立的"标签: 内容"对——调查目标是什么、调查对象是谁、调查方法是什么……各行互相独立，没有"上面定义列名、下面填数据"的关系。

→ **标注**：`header_rows: 0`

## 案例1E：表头判断常见错误

| 错误 | 为什么错 | 正确做法 |
|------|---------|---------|
| 看到"调查目标 | xxx"就设 header_rows=1 | 这是表单结构，不是数据表 | header_rows=0 |
| 看到第一行是标题行（合并）就设 header_rows=1 | 标题行和表头行是两回事 | 看下面行是不是真的在定义数据列 |
| 对比表设 header_rows=2 因为觉得首列也是表头 | header_rows 只管行方向（顶部的几行） | header_rows=1 |
| 排版表的空行/合并结构被误认为表头 | 排版表就没有表头概念 | header_rows=0 |

## 案例2：含表格的材料 — segments 结构

### 原文（content.md 中的占位符）

```
下表为某地区2020-2024年人口迁移数据统计表。

{{table:table_001}}

（注：表中数据为年末统计值）
```

> `{{table:table_NNN}}` 是 Step1 生成的表格占位符。对应表格的结构化数据在 `{工作目录}/清洗产物/tables.json` 中，需读取后原样复制到 segments。

### tables.json 中的表格数据

```json
{
  "tables": [
    {
      "table_id": "table_001",
      "rows": 5,
      "cols": 4,
      "data": [
        ["年份", "迁入人口（万人）", "迁出人口（万人）", "净迁移率（%）"],
        ["2020", "12.5", "8.3", "+4.2"],
        ["2021", "15.2", "9.1", "+6.1"],
        ["2022", "18.6", "10.5", "+8.1"],
        ["2023", "22.3", "12.8", "+9.5"]
      ],
      "spans": []
    }
  ]
}
```

### 标准标注

```json
{
  "id": "material_005",
  "content": "",
  "guide_sentence": "完成下列要求。",
  "segments": [
    {
      "type": "text",
      "content": "下表为某地区2020-2024年人口迁移数据统计表。"
    },
    {
      "type": "table",
      "data": {
        "rows": 5,
        "cols": 4,
        "data": [
          ["年份", "迁入人口（万人）", "迁出人口（万人）", "净迁移率（%）"],
          ["2020", "12.5", "8.3", "+4.2"],
          ["2021", "15.2", "9.1", "+6.1"],
          ["2022", "18.6", "10.5", "+8.1"],
          ["2023", "22.3", "12.8", "+9.5"]
        ],
        "spans": [],
        "header_rows": 1,
        "table_role": "data",
        "table_style": "grid"
      }
    },
    {
      "type": "text",
      "content": "（注：表中数据为年末统计值）"
    }
  ]
}
```

### 关键判断

| 判断点 | 正确做法 | 常见错误 |
|--------|----------|----------|
| **识别占位符** | `{{table:table_NNN}}` 是表格占位符，去 `tables.json` 找对应数据 | 丢弃占位符或当作文本 |
| **使用 segments** | 材料包含文本+表格+文本的混合内容，必须使用 `segments` 数组 | 把表格强行转成纯文本 |
| **content 为空** | 当使用 `segments` 时，`content` 字段留空 `""` | 同时填写 `content` 和 `segments` |
| **spans 原样复制** | 将 `tables.json` 中的 `rows`、`cols`、`data`、`spans` 全部原样复制 | 忽略 `spans` 字段或修改数据 |
| **表格顺序** | 按"文本→表格→文本"的原文出现顺序排列 | 把表格放到最前面 |
| **header_rows 必填** | 根据案例1A-1D的判断方法，从 tables.json 读取并根据表格内容重新判断 | 默认填 1 或不填 |
| **table_role 必填** | 数据表填 "data"，表单/访谈填 "material"，排版表填 "layout"，不确定填 "unknown" | 全部填 "unknown" |
| **注释放 segments** | "（注：...）"是表格的补充说明，作为独立的 text segment | 放在表格 data 中 |
| **注释位置必须在表格后** | 注释 segment 必须紧跟在表格/图片 segment **之后**，不可放在表格之前 | 把注释作为引导文字放在表格前 |
| **注释不合并到 content** | 注释属于表格/图片的补充说明，不是材料正文，不允许写入 `material.content` | 把注释拼到 content 末尾 |
| **注释含①②序号换行** | 注释中 ①②③④ 序号必须用 `\n` 分隔，每个序号独占一行 | 把"①XX②YY"塞在一段无换行 |

### 注释格式规范（重点）

**适用范围**：所有出现在图片或表格下方的说明文字，包括：
- `注：xxx`
- `（注：xxx）`
- `注释：xxx`
- `备注：xxx`
- `说明：xxx`（紧跟在表格/图片后的）

**处理规则**：

1. **作为独立 text segment**：注释必须是 segments 数组中独立的 `type: "text"` 条目，不可合并到材料正文 content 字段。

2. **位置必须在被注释对象之后**：注释 segment 必须紧跟在表格/图片 segment **之后**，保持原文档"表格→注释"的视觉顺序。

3. **含①②③序号必须换行**：注释中如含 ①②③④⑤⑥⑦⑧⑨⑩ 等中文数字序号，**必须用 `\n` 分隔每个序号**，让排版脚本能按序号拆分换行渲染。

**正确写法示例**：

```
原文（content.md）：
注：①劳动年龄人口老化比：劳动年龄(15—64岁)中45岁以上的人口占比。
②抚养比：少儿人口数和老年人口数与劳动年龄人口数之比。
```

```json
{
  "type": "text",
  "content": "注：①劳动年龄人口老化比：劳动年龄(15—64岁)中45岁以上的人口占比。\n②抚养比：少儿人口数和老年人口数与劳动年龄人口数之比。"
}
```

**错误写法**：
- ❌ `"注：①XXX②YYY"` （无换行，排版时 ② 紧跟 ①）
- ❌ `"①XXX\n②YYY"` （去掉了"注："前缀）
- ❌ `"注：①XXX\n\n②YYY"` （多一个空行，导致排版时出现空白段落）
- ❌ 把注释合并到材料正文 content 末尾

## 案例1B：含合并单元格的表格 — spans 字段

### tables.json 中的表格数据

```json
{
  "tables": [
    {
      "table_id": "table_002",
      "rows": 5,
      "cols": 4,
      "data": [
        ["类别", "", "数量", "占比（%）"],
        ["人口迁入", "城镇", "1250", "45.2"],
        ["", "乡村", "890", "32.1"],
        ["人口迁出", "城镇", "560", "20.2"],
        ["", "乡村", "780", "28.1"]
      ],
      "spans": [
        {"row": 0, "col": 0, "rowspan": 1, "colspan": 2},
        {"row": 1, "col": 0, "rowspan": 2, "colspan": 1},
        {"row": 3, "col": 0, "rowspan": 2, "colspan": 1}
      ]
    }
  ]
}
```

> **说明**：`data` 是完整的 rows×cols 网格（每个位置都有文本，合并区域留空），`spans` 描述了3处合并：
> - 第0行第0列横向合并2列（"类别"跨2列）
> - 第1行第0列纵向合并2行（"人口迁入"跨2行）
> - 第3行第0列纵向合并2行（"人口迁出"跨2行）

## 案例2：注意事项识别与拆分

### 原文

```
注意事项：
1.本试卷共6页，满分100分，时间75分钟。
2.答卷前，考生务必将自己的姓名和准考证号填写在答题卡上。
3.回答选择题时，选出每小题答案后，用2B铅笔把答题卡上对应题目的答案标号涂黑。如需改动，用橡皮擦干净后，再选涂其他答案标号。涂写在本试卷上无效。
4.作答非选择题时，将答案书写在答题卡上，书写在本试卷上无效。
5.考试结束后，监考员将答题卡按顺序收回，装袋整理；试卷不回收。
```

### 标准标注

```json
{

```

### 关键判断

| 判断点 | 正确做法 | 常见错误 |
|--------|----------|----------|
| **双格式保留** | `notes` 保留原文全文（兼容旧格式），`notes_items` 提供结构化版本 | 只保留一种格式 |
| **标题项** | "注意事项"作为 `{type: "title"}` 项 | 把"注意事项"混入第1条的 `content` |
| **内容不含序号** | `content` 字段不含序号前缀（如"1."），序号在 `number` 字段中 | `content` = "1.本试卷..."（序号重复） |
| **序号在 number 字段** | `number` = "1"、"2"... 为纯数字字符串 | `number` = "(1)" 或缺失 |

## 案例3：分区标题与引导语合并

### 原文

```
一、选择题：本题共15小题，每小题3分，共45分。在每小题给出的四个选项中，只有一项是符合题目要求的。
```

### 标准标注

```json
{
  "id": "section_001",
  "type": "选择题",
  "title": "一、选择题：本题共15小题，每小题3分，共45分。在每小题给出的四个选项中，只有一项是符合题目要求的。",
  "instructions": []
}
```

### 关键判断

| 判断点 | 正确做法 | 常见错误 |
|--------|----------|----------|
| **标题与引导语在同一段** | "在每小题给出的四个选项中..."与题型标题在同一段落，合并到 `title` 字段 | 把"在每小题..."拆到 `instructions` |
| **instructions 为空** | 引导语不单独成段时，`instructions` 为 `[]` | 无论如何都往 `instructions` 里加内容 |

**对比：当引导语单独成段时**：

```
一、选择题：本题共15小题，每小题3分，共45分。

在每小题给出的四个选项中，只有一项是符合题目要求的。
```

此时应标注为：

```json
{
  "title": "一、选择题：本题共15小题，每小题3分，共45分。",
  "instructions": ["在每小题给出的四个选项中，只有一项是符合题目要求的。"]
}
```

## 案例4：卷标题与题型标题（header_blocks 使用）

### 场景A：仅有卷标题，无题型标题（如重庆部分区高一期末）

```
第I卷（选择题共60分）

本卷共30个小题。每小题2分，共60分。在每小题给出的四个选项中，只有一项是最符合题目要求的。
```

### 标准标注

```json
{
  "id": "section_001",
  "type": "选择题",
  "header_blocks": [
    {"type": "volume_title", "content": "第I卷（选择题共60分）"}
  ],
  "title": "",
  "instructions": ["本卷共30个小题。每小题2分，共60分。在每小题给出的四个选项中，只有一项是最符合题目要求的。"]
}
```

### 场景B：仅有题型标题，无卷标题（最常见）

```
一、选择题：本题共15小题，每小题3分，共45分。在每小题给出的四个选项中，只有一项是符合题目要求的。
```

### 标准标注

```json
{
  "id": "section_001",
  "type": "选择题",
  "header_blocks": [],
  "title": "一、选择题：本题共15小题，每小题3分，共45分。在每小题给出的四个选项中，只有一项是符合题目要求的。",
  "instructions": []
}
```

### 场景C：两者共存（卷标题 + 题型标题）

```
第I卷（选择题 共48分）

一、选择题：本题共16小题，每小题3分，共48分。在每小题给出的四个选项中，只有一项是符合题目要求的。
```

```json
{
  "id": "section_001",
  "type": "选择题",
  "header_blocks": [
    {"type": "volume_title", "content": "第I卷（选择题 共48分）"}
  ],
  "title": "一、选择题：本题共16小题，每小题3分，共48分。在每小题给出的四个选项中，只有一项是符合题目要求的。",
  "instructions": []
}
```

### 场景D：卷标题 + 注意事项（含标题和编号条目）

```
第II卷（非选择题 共40分）

注意事项：
1. 本卷共2个小题，共40分。
2. 请用0.5毫米黑色签字笔将答案写在答题卡上。
3. 考试结束后，将答题卡和试卷一并交回。
```

```json
{
  "id": "section_002",
  "type": "非选择题",
  "header_blocks": [
    {"type": "volume_title", "content": "第II卷（非选择题 共40分）"},
    {"type": "notes", "content": "注意事项：\n1. 本卷共2个小题，共40分。\n2. 请用0.5毫米黑色签字笔将答案写在答题卡上。\n3. 考试结束后，将答题卡和试卷一并交回。"}
  ],
  "title": "",
  "instructions": [],
  "questions": [...]
}
```

> **notes 格式说明**：标题 `"注意事项："` 单独占行，每个条目以序号 `1.` / `2.` / `3.` 开头，以 `\n` 分隔。也支持单行写法 `"注意事项：1. 条目一2. 条目二"`，排版代码会自动按序号拆分。

### 关键判断

| 判断点 | 正确做法 | 常见错误 |
|--------|----------|----------|
| **卷标题** | "第I卷""第II卷""第Ⅲ卷" → `header_blocks[].type: "volume_title"` | 填入 `title` 或忽略 |
| **分区内注意事项** | 分区内的注意事项 → `header_blocks[].type: "notes"` | 与文档级 `meta.notes_items` 混淆 |
| **顺序保真** | `header_blocks[]` 严格按原文顺序排列 | 重排或合并不同位置的块 |
| **两者共存** | 卷标题 + 题型标题 → 卷标题在 header_blocks，题型标题在 title | 只保留一个，丢弃另一个 |
| **仅有卷标题** | `header_blocks[]` 含 volume_title，`title` 填空字符串 `""` | `title` 不填（Schema 要求必填） |
| **无头部块** | `header_blocks: []`（空数组，不可省略） | 省略 `header_blocks` 字段 |
| **排版样式** | volume_title → "第几卷"，notes → "注意事项内容"，instructions → "Body Text" | 用同一个样式渲染所有块 |
